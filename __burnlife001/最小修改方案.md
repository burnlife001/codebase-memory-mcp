# 最小修改方案:pro 特性移植到上游新基线

> 基线:upstream/main = `97ce23f9`(2026-07-23)。前置决定:**放弃 explore 工具**(与上游 tree-format/TOON 省 token 哲学冲突)。

## 核心策略:不做 git merge/rebase,改「新基线 + 精选补丁重放」

fork 基点后上游有 872 个提交,且 pro 的 explore 代码深嵌 `mcp.c`(上游改动最密集的文件,273+ 行冲突面)。直接 merge 会把精力耗在已决定放弃的代码上。
**做法:pro 分支 reset 到 upstream/main,把保留项做成 5 个独立小补丁逐个重放,每个独立 commit、独立可验证。** 净改动估计 ~140 行。

## 二、保留项冲突点盘点与处置(按重放顺序)

### 补丁 1 — git2 alloc.h( pro `e51d79c`,~3 行)
- **文件**:`internal/cbm/cbm.c`(上游 23 个提交碰过)
- **冲突风险:极低**。只在 include 区加一行 `#include <git2/sys/alloc.h>`,不碰逻辑。
- **前置验证**:先在上游基线编译,确认 `git_allocator` 告警/错误仍存在;上游若已不需要则整项放弃。

### 补丁 2 — Swift enum/protocol 成员去重(pro `2f34fe1`,~6 行)
- **文件**:`internal/cbm/extract_defs.c` 的 `push_class_body_children`(上游 6263 行)
- **冲突风险:低,几乎必然文本冲突但解决平凡**。上游往同一个 body 容器清单加了 Groovy `closure` 行——两边是同一列表的不同追加,合并时保留双方即可。
- **改动**:清单中追加 `enum_class_body` / `protocol_body` 两个 strcmp 分支。
- **验证**:Swift 项目索引后 dup_nodes = 0(pro 基准:LingoLearn 38→0)。

### 补丁 3 — EnumCase 节点(pro `79a420f` 的 M2-c,~60 行)
- **文件**:`extract_defs.c` + 3 处注册表
- **冲突风险:极低,近干净套用**:
  - `is_enum_member_kind`(上游 4750 行)与 fork 基点**逐字相同**,`enum_entry` 一行直接加;
  - `extract_enum_members` 的 swiftish 分支同理;
  - 3 处注册表白名单(`pass_definitions.c:338`、`pass_parallel.c:1259`、`pipeline_incremental.c:525`)上游形状未变(Function/Method + type_like + Variable/Field),各追加 `|| strcmp(label, "EnumCase") == 0`。
- **验证**:Swift/Kotlin enum `case a, b, c` 产出 3 个 EnumCase 节点;`Type.case` 引用可解析。

### 补丁 4 — Swift Enum/Actor 标签 + extension 防 clobber(pro `13bfbe9` 精简版,~30 行)
- **文件**:`extract_defs.c` 的 `extract_class_def` + `helpers.c` 谓词
- **冲突风险:中,必然手工重放**。上游在同一区域插入了 Rust/Swift/D Struct 逻辑(3920 行的 declaration_kind 块),pro 原 hunk 锚点已失效。
- **改动**(相比 pro 原版大幅缩水):
  1. 在 `extract_class_def` 上游 3920 块之后追加:declaration_kind 为 `enum`→`Enum`、`actor`→`Actor`(struct 分支**不搬**,上游已做);
  2. `extension` 分支保留 pro 的审查修复:提取成员但**不发 type def**,避免 last-write-wins upsert 把真实类型的标签冲掉(上游无此处理,bug 大概率仍在——移植后用 `struct X{}` + `extension X: P {}` 验证 X 保持 Struct);
  3. `helpers.c:160` 谓词加 `"Actor"` 一行(`Enum` 已在谓词中,免费获得全部消费点)。
- **原 pro 的 14 处 allowlist 改动全部不需要**——上游已谓词化。移植后需抽查非谓词消费点(search_code 排序、store.c SQL)对 Actor 的行为。
- **验证**:LingoLearn 基准 Struct:38/Enum:20/Class:6;INHERITS/CALLS 边不丢。

### 补丁 5 — cypher `type(r)` 聚合修复(pro `79a420f` 的 M2-b1,~40 行)
- **文件**:`src/cypher/cypher.c`(上游 22 个提交碰过)
- **冲突风险:中,纯手工重放**。7 个目标函数(with_agg_build_key/find_or_create/accumulate、ret_agg_build_key/accumulate/emit_row 等)上游都在,但 `ret_agg_build_key` 签名已变(多了 `vals/valbufs`),pro 的 diff 无法直接 apply。
- **有利条件**:上游部分路径已自行改用 `project_item`(3912、4237、4355 行),与 pro 修复同方向——实际要做的只是把各处分组键/累加/输出的函数名判断改成 `is_aggregate_func()` 门控,逐 site 对照即可。
- **验证**:`RETURN type(r), count(*)` 返回按类型的多行(行数 = 边类型数,计数和 = 总边数),而非塌缩成一行。
